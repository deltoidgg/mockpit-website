# Quick Start

This guide adds MockPit to a vanilla browser app. React and MSW have their own guides after
this page.

## Install

<Tabs groupId="package-manager">
  <TabItem value="pnpm" label="pnpm" default>

```sh
pnpm add -D @mockpit/core @mockpit/browser @mockpit/devtools
```

  </TabItem>
  <TabItem value="npm" label="npm">

```sh
npm install --save-dev @mockpit/core @mockpit/browser @mockpit/devtools
```

  </TabItem>
  <TabItem value="yarn" label="yarn">

```sh
yarn add --dev @mockpit/core @mockpit/browser @mockpit/devtools
```

  </TabItem>
</Tabs>

## Configure

Create a resource map and a section map. Resource keys are the stable names MockPit uses in
devtools, reports, and capture policies.

```ts title="mockpit.config.ts"
import { defineMockPitConfig, defineResource, defineSection } from "@mockpit/core";

export const config = defineMockPitConfig({
  project: "my-app",
  mode: { default: "mock" },
  resources: [
    defineResource({
      key: "customers.list",
      label: "Customer list",
      match: { method: "GET", url: "/api/customers" },
      assess: (data: { customers: unknown[] }) => ({
        empty: data.customers.length === 0,
        coverage: { present: data.customers.length > 0 ? 1 : 0, total: 1 },
      }),
      fallback: () => import("./fixtures/customers").then((module) => module.customers),
      fallbackSource: "src/fixtures/customers.ts",
    }),
  ],
  sections: [
    defineSection({
      route: "/customers",
      id: "customers.table",
      label: "Customer table",
      resources: ["customers.list"],
    }),
  ],
});
```

## Create The Client

```ts title="src/mockpit.ts"
import { createMockPitClient } from "@mockpit/browser";
import { defineAllMockPitElements, mountMockPitDevtools } from "@mockpit/devtools";
import { config } from "../mockpit.config";

export const mockpit = createMockPitClient({ config });

defineAllMockPitElements();
mountMockPitDevtools({ client: mockpit });
```

## Instrument A Request

```ts
const data = await mockpit.fetch("customers.list", "/api/customers");
```

MockPit records the source kind, route, status, field coverage, fallback use, and any
resource remediation you configured.

## Mark UI Copy

Use custom elements for visible values that can be mistaken for live evidence.

```html
<mockpit-mark
  data-resource-key="ui.customers.emptyState"
  data-source-kind="hardcoded"
  data-label="Customer empty state copy"
>
  No customers match this filter.
</mockpit-mark>
```

## What Good Looks Like

- Each API-backed UI section has at least one resource key.
- Fallback resources include `fallbackSource` and a remediation note when useful.
- Hardcoded or authored fallback copy is marked as presentation data.
- Capture-critical routes have a capture policy before demos or recordings.
